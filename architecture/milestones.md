# CORTEX milestones

Tracks what remains to deliver the end-to-end system in [full-architecture.md](./full-architecture.md). Status: `[x]` done and tested, `[~]` built but not verified end to end, `[ ]` not started. Update this file in the same commit that changes a status.

## M1. Secure foundation: done

- [x] Go API, PostgreSQL, private object storage (SeaweedFS), profile ownership
- [x] Purpose-based consent, audit events, error/response envelope
- [x] Dev-token sessions with hashed opaque bearer tokens
- [x] Secrets generated by `scripts/bootstrap-env`; compose fails fast without them

## M2. Document workflow: mostly done

- [x] Signed upload, worker extraction, review, approve into observations
- [x] Catalog-driven extraction with reference range and report date read from the report
- [x] Unknown labels queue research
- [ ] OCR for images and scanned PDFs (choose engine, evaluate, add review warnings)
- [ ] Durable job/outbox semantics before scaling workers
- [ ] Go tests for the worker and object-store packages

## M3. Retrieval and models: done

- [x] Pinned Hugging Face embedder (`bge-small-en-v1.5`), 384 dimensions, baked into the image
- [x] pgvector plus full-text hybrid search, optional cross-encoder rerank
- [x] Ollama explanation adapter behind the safety policy
- [ ] Model registry entry and evaluation report for each promoted model
- [ ] Retrieval-quality evaluation set (recall at k) that is not hard-coded product data

## M4. Learned knowledge: built, needs verification

- [x] Research agent (LOINC, UCUM, MedlinePlus, PubMed) behind a host-allowlisted fetcher
- [x] Pending, approve and reject flow, bulk approve, admin gating
- [x] Queue with retry and back-off; discovery on first start
- [~] Rebuilt stack verified with the latest code (research routing, date and range extraction)
- [ ] Learn reference ranges from reviewed reports, with a minimum sample and a reviewer step
- [ ] Learn abbreviations and synonyms from reviewed labels
- [ ] Review queue UI in the iOS app (or a small admin web page)
- [ ] Remove the remaining hard-coded routing terms (`LAB_TERMS`, `RESEARCH_TERMS`) and consent purpose list from code

## M5. Controlled orchestration: partial

- [x] LangGraph health-question workflow with abstention and safety checks
- [x] Read-only MCP server with scoped, short-lived tokens
- [ ] AI service as an MCP client: workflow tools call MCP instead of receiving pushed context
- [ ] Tool allowlist, per-call limits and audit coverage tests

## M6. Identity and security: not started

- [ ] OIDC provider integration (Sign in with Apple), replacing dev-token sessions
- [ ] Token refresh, revocation and device sessions
- [ ] Admin role from the identity provider instead of `CORTEX_ADMIN_OWNER_IDS`
- [ ] Encryption at rest for objects and backups; key management
- [ ] Data export and account deletion, including embeddings and object storage
- [ ] Security review and dependency scanning in CI

## M7. Records and lab intelligence

- [x] Observations, history, trends, and corrections
- [ ] Reference range comparison using learned ranges (M4)
- [ ] Unit conversion between learned units
- [ ] Source-document links from every answer fact

## M8. Verified research in answers

- [x] Approved PubMed abstracts retrieved and cited as `[R#]`
- [~] Citation display in iOS (decoding tested; app not compiled)
- [ ] Evidence-type labels (guideline, review, trial) and publication dates in answers
- [ ] Re-verification of sources and retraction checks

## M9. iOS app

- [~] Consent, upload, review, approve, ask flow written; **never compiled (needs Xcode)**
- [ ] Build and run in Simulator; fix compile errors
- [ ] UI tests for the main flow
- [ ] Offline handling and error states
- [ ] Accessibility pass

## M10. Devices and vision

- [ ] HealthKit import with its own consent and provenance
- [ ] Camera observations with their own consent, evaluation and deletion path

## M11. Observability and operations

- [ ] OpenTelemetry traces across API, worker, AI service and tool calls
- [ ] Metrics: queue age, extraction outcomes, latency, retries, model errors
- [ ] No health content in logs (test enforced)
- [ ] CI pipeline: `go vet`, `go test -p 1` with a Postgres service, `pytest`, image build
- [ ] Backup and restore runbook, tested

## M12. Medical imaging and care navigation (later)

- [ ] DICOM/MONAI/OHIF design review
- [ ] Consultation preparation and optional follow-up integrations with user confirmation

## Suggested order

1. Verify M4 on the rebuilt stack, then commit any fixes.
2. Compile and run the iOS app (M9), since nothing there has been tested.
3. Identity (M6) before any real user data.
4. Learned reference ranges (M4) and range comparison (M7).
5. OCR (M2), MCP client (M5), observability and CI (M11).
6. Devices, vision and imaging (M10, M12) last, each as a separate consented domain.
